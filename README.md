מראה של הסקילים שלי ברמת חשבון, כדי שיהיה מקום אחד לקרוא אותם, להשוות ביניהם,
ובהמשך גם לנהל אותם.

**פרטי בכוונה.** חלק מהסקילים כאן כתובים עליי אישית: ב‑`emotional-sharing` יש
דוגמאות שנוגעות לתרופות ולמצב רוח, וב‑`idea-storm` מופיעים שמות הפרויקטים שלי
ומה נכשל בכל אחד. הריפו הזה לא אמור להפוך לציבורי.

## מה יש כאן

| נתיב | מה הוא מכיל |
| --- | --- |
| `skills/` | תיקייה לכל סקיל, מועתקת כמו שהיא מ‑`~/.claude/skills` |
| `INDEX.md` | טבלה שנוצרת אוטומטית, עם כל סקיל והתיאור שלו |
| `viewer/index.html` | גריד כרטיסים עם חיפוש, תרגום, מקור מלא וניתוח חפיפות |
| `viewer/translations.json` | תרגומי התיאורים לעברית, עם חתימת המקור שלהם |
| `scripts/snapshot-skills.sh` | מרענן את `skills/` מתוך הסשן הנוכחי |
| `scripts/build-index.py` | מייצר מחדש את `INDEX.md` |
| `scripts/build-viewer.py` | מייצר מחדש את `viewer/index.html` |
| `scripts/markdown.py` | ממיר מארקדאון ל‑HTML עבור תצוגת המקור |

## איך הצילום עובד

סקילים שמוגדרים ב‑claude.ai נטענים אוטומטית לקונטיינר של כל סשן Claude Code,
לתוך `~/.claude/skills`. בתוך הסשן הם קבצים רגילים לגמרי, ולכן כדי לתפוס אותם
לא צריך API ולא אינטגרציה עם האפליקציה, אלא העתקה פשוטה.

```text
claude.ai  ->  (אוטומטית, בפתיחת סשן)         ->  ~/.claude/skills
           ->  (scripts/snapshot-skills.sh)   ->  skills/  ->  git
```

לרענון, מתוך סשן Claude Code שהריפו הזה משובט בו:

```bash
bash scripts/snapshot-skills.sh
python3 scripts/build-index.py
python3 scripts/build-viewer.py
git add -A && git commit -m "רענון צילום הסקילים" && git push
```

הצילום עושה mirror ולא merge, כך שסקיל שנמחק ב‑claude.ai נעלם גם כאן, והריפו
משקף את החשבון כפי שהוא באמת ולא נשאר עם רוחות רפאים.

## הכיוון שלא קיים

אין סנכרון חזרה. עריכה של `SKILL.md` כאן לא משנה כלום במה שקלוד טוען בפועל,
וזה עדיין דורש העלאה ידנית בהגדרות החשבון ב‑claude.ai. הריפו הזה הוא מראה,
לא מקור אמת, וכל כלי שייבנה עליו צריך להניח את זה מראש.

## למה האינדקס הוא החלק השימושי

`description` הוא השדה היחיד שקובע אם סקיל נטען בכלל. עם 28 סקילים התיאורים
מתחילים לדרוך זה על זה בשקט, ושניים שטוענים לבעלות על אותו סוג בקשה יתחרו בלי
שום סימפטום גלוי. `INDEX.md` מציב את כולם זה לצד זה, וכך ההתנגשויות נעשות
קריאות.

## הצופה

`viewer/index.html` הוא קובץ אחד שנפתח בדפדפן, בלי שרת ובלי התקנה. יש בו גריד
כרטיסים, חיפוש חי בשם ובתיאור, סינון לפי שפה או לפי חפיפה, וסקציית התנגשויות.

הקובץ עומד בפני עצמו, כולל כל 380KB של מקורות הסקילים, ולכן אפשר פשוט להוריד
אותו פעם אחת ולפתוח מהטלפון. הגופנים נטענים מ‑Google Fonts ונופלים לגופני מערכת
כשאין רשת.

### תצוגת המקור

לחיצה על כרטיס פותחת את ה‑`SKILL.md` המלא בחלון, לא רק את התיאור. החלון הוא
`<dialog>` טבעי, כך ש‑Esc, שכבת הרקע והחזרת המיקוד עובדים בלי קוד. הכרטיס נגיש
גם במקלדת ונפתח ב‑Enter או ברווח. הכפתור "הצג הכל" מרחיב את התיאור במקום ולא
פותח את החלון.

הרינדור נעשה בזמן הבנייה על ידי `scripts/markdown.py`, ממיר קטן ומכוון: הוא
מכסה את מה שהקורפוס באמת משתמש בו — כותרות, בלוקי קוד, טבלאות, רשימות, ציטוטים
והדגשות — ולא יותר. כל בלוק מקבל `dir="auto"`, כך שקטעים בעברית ובאנגלית באותו
מסמך כל אחד קורא נכון, ובלוקי קוד נשארים LTR. הטקסט עובר escape לפני שנוצרת
ממנו שום תגית, כך ש‑`SKILL.md` לא יכול להזריק HTML לעמוד.

### איך מחושבת החפיפה

התיאורים מנוקים ממילות חיבור וממונחים שחוזרים ביותר מ‑45% מהם. מה שנשאר הוא
אוצר המילים המבחין, ועליו מחושב מדד Jaccard בין כל זוג.

אבל חפיפה לשונית לבדה מטעה, והקורפוס הזה מדגים בדיוק למה: שלושת הסקילים
שיוצרים סקילים מקבלים ציון אפסי זה מול זה, כי התיאורים שלהם נכתבו כדי להבדיל
ולכן נמנעים במכוון מהמילים של השני. לכן כל זוג נושא גם את השאלה אם אחד
התיאורים מזכיר את השני בשמו.

הצירוף הוא מה שנותן את התשובה. **זוג שחולק אוצר מילים ולא מפנה לשני הוא זה
שדורש החלטה**, וזוג שכן מפנה כבר טופל ויורד לתחתית הרשימה. רק זוגות מהסוג
הראשון מקבלים תגית על הכרטיס.

זו הערכה גסה ולא הוכחה, והיא נועדה לכוון את העין ולא להחליף שיפוט.

### תרגום התיאורים

21 מהתיאורים כתובים באנגלית. `viewer/translations.json` מחזיק להם תרגום לעברית,
והכפתור "תרגום לעברית" מחליף ביניהם.

**המקור הוא מה שמוצג כברירת מחדל, וזה לא שרירותי.** התיאור באנגלית הוא מה
שקובע בפועל אם הסקיל נטען, והוא הארטיפקט שנבדק כאן. התרגום הוא עזר קריאה
בלבד, ולכן כרטיס מתורגם נושא תגית שמסמנת זאת.

כל תרגום שומר חתימה של התיאור שממנו נוצר. אם התיאור במקור השתנה, החתימות לא
יתאימו, הבנייה תדפיס אזהרה והכרטיס יסומן כ"תרגום לא מעודכן". בלי זה תרגום ישן
היה ממשיך להיראות תקין אחרי שהמקור זז מתחתיו.

מונחים טכניים כמו <span dir="ltr">.docx</span> או
<span dir="ltr">validate-skill.sh</span> נעטפים אוטומטית ב‑`<bdi>` בזמן הבנייה.
בלי זה הנקודות והלוכסנים, שהם ניטרליים מבחינת כיווניות, נודדים לקצה הלא נכון של
המונח בתוך זרימה עברית, וסיומת קובץ נראית שבורה.

החיפוש סורק גם את התרגום, כך ששאילתה בעברית מוצאת סקיל שהתיאור שלו באנגלית בלבד.
